## [2026-09-30 to 2026-10-08 | Milestone 2 (M2-US01 through M2-US11) — v0.2.0 Delivery]

### 1. Task Objective
Deliver complete aircraft connection lifecycle, multi-device rules, telemetry-based readiness checks, and reproducible v0.2.0 release package.

### 2. Failure & Iteration Log (What failed & how it was resolved)
* **Issue 1 (Phantom Reconnect Loop):**
  - *Symptom:* When RC and drone were OFF and user clicked "Reconnect", 15s watchdog timed out and showed error banner, but UI immediately bounced back into "Connecting" once.
  - *Root Cause:* `_refreshDeviceLists()` was re-evaluating auto-connect without checking if an attempt had already failed/cancelled in that session.
  - *Code Edit:* Added `!_hasConnectionFailed && !_hasCancelled && !_autoConnectAttempted` guards to auto-connect trigger in `custom/qml/PulseGCS/ConnectAircraftPanel.qml` (lines 1018–1040) and set `_autoConnectAttempted = true` immediately upon any manual or automated connection attempt in `connectDevice()` (line 1158).
  - *Working State:* Auto-connect triggers once on boot if 1 device is paired; if cancelled or failed, it returns to the scan panel and stays there permanently.

* **Issue 2 (Multi-Device Auto-Connect Ambiguity):**
  - *Symptom:* When multiple paired aircraft exist, auto-connect could connect to the wrong drone on an active airfield.
  - *Code Edit:* In `_refreshDeviceLists()`:
    - `_pairedDevices.length === 1`: Auto-connect to connecting panel.
    - `_pairedDevices.length > 1`: Suppress auto-connect (`_autoConnectAttempted = true`), stay on paired list with individual "Reconnect" buttons for each aircraft.
    - `_pairedDevices.length === 0`: Auto-start RF discovery scan.

* **Issue 3 (Notice Bar Redundant Buttons):**
  - *Symptom:* Notice bars across cancel, timeout, and disconnect showed redundant action buttons ("Retry", "Search Again").
  - *Code Edit:* Enforced `actionText: ""` and empty `onActionClicked: {}` across all `PulseGCSNoticeBar` instances. All notice bars are now strictly pure informational banners; operator interacts solely through primary screen controls.

* **Issue 4 (False "RC Not Ready" Warning):**
  - *Symptom:* Status pill always displayed "RC NOT READY" even when FlyView was green.
  - *Root Cause:* Evaluated `_activeVehicle.vehicle.rcRSSI.value === 255` on non-RC telemetry links.
  - *Code Edit:* Replaced with standard QGC `healthAndArmingCheckReport.canArm`, `readyToFly`, and sensor health states (`custom/qml/PulseGCS/ConnectAircraftPanel.qml` lines 2460–2515).

* **Issue 5 (Unpairing Confirmation & Watchdog):**
  - *Code Edit:* Added modal dialog `unpairConfirmPopup` before unpairing. Added 30s `pairingWatchdog` with timeout error banner.

* **Issue 6 (Version Bump to 0.2.0):**
  - *Code Edit:* Bumped `PULSEGCS_APP_VERSION` to `0.2.0` in `custom/cmake/CustomOverrides.cmake`. Built and verified `PulseGCS.apk` (versionName `0.2.0`, versionCode `660200000`, SHA-256: `31cfbe1245f8f80bdb2d6f7961b372c8b9637013758ee468e42b9262f773a1e8`).
